## Shared combat correctness seams

- The kill event carries `{npc}` (`src/game3_systems.js:887`) but the tutorial listener discards it. It also discards the attack's actual style. Projectile resolution does retain `xpTok` (`src/game3_systems.js:584`), while `applyHit` calls `killNpc(npc)` without passing that provenance (lines 690–704). Switching equipment or arming a spell while a projectile travels can therefore credit a different current style. This is a source-derived risk, not a reproduced browser failure.
- `killNpc` emits `npcKilled` before its `noQuest` guard (lines 887–890), so `noQuest` is not a tutorial styled-kill suppression mechanism. Duel wins return before this event (lines 868–875).
- `src/config.js:19` sets `worldNpcSpawns:false`; ordinary `spawnNpc` rejects spawns unless forced (`src/game3_systems.js:383`). Base Holm chunks carry empty spawns (`src/world_v2_holm.js:44`) and building bundle authoring emits empty spawns (`src/world_v2_bundle_authoring.js:50`). Together with future-only sockets, this is positive source evidence that the named teaching encounters are not implemented through these providers. It is not an exhaustive asset inventory or live scene count.
- The old comment that NPC work is deferred in `src/tutorial_holm.js:19–23` is historical implementation explanation, not current authorization or permission to omit the lessons.
